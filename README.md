# EatRight: 价值对齐的餐食推荐助手

EatRight 是一个用于 AI 伦理课程项目的轻量级原型。它把“今天吃什么”的日常推荐问题设计成一个可解释、可调节、带公平性约束和隐私保护演示的推荐系统。

## 项目目标

普通餐食推荐器容易出现营养偏见、文化单一化、信息茧房和不透明决策。EatRight 的设计目标不是单纯追求点击率，而是把以下伦理原则显式写入系统：

- 用户自主：用户可以调节“美味、健康、新奇”的价值权重。
- 透明解释：每条推荐都显示推荐理由和综合得分。
- 公平多样：推荐列表会监测菜系分布，避免单一菜系过度集中。
- 反信息茧房：使用 UCB 探索项，让较少出现的菜品和菜系仍有机会被推荐。
- 隐私保护：反馈仅保存在本地，并提供差分隐私噪声聚合演示。

## 项目结构

```text
.
├── app.py                  # Streamlit 用户界面
├── data/
│   └── dishes.csv          # 45 道菜品的模拟数据
├── src/
│   ├── recommender.py      # 多目标推荐与 UCB 探索
│   ├── fairness.py         # 菜系分布和总变差距离约束
│   ├── explainer.py        # 推荐解释和目标函数说明
│   └── privacy.py          # 差分隐私聚合演示
├── requirements.txt
└── README.md
```

运行后会生成 `.eatright_state.json`，用于保存本地试用历史。该文件不需要提交。

## 核心算法

每道菜的基础得分由多目标加权得到：

```text
S = w_taste * taste + w_health * health + w_novelty * novelty + UCB_bonus - trend_penalty
```

- `taste`：由菜品平均评分归一化得到。
- `health`：综合低热量、高蛋白、低脂肪三个指标。
- `novelty`：结合最近历史菜系和 UCB 探索奖励，减少重复推荐。
- `trend_penalty`：对网红标签加入轻微惩罚，并在解释中显式告知用户。

推荐列表生成后，系统计算当前列表内部的菜系分布与“列表内菜系均匀分布”的总变差距离：

```text
D_TV = 1/2 * sum(|p_c - q_c|)
```

当短推荐列表过度集中在少数菜系时，系统会用公平性重排机制补入更少出现的菜系，并在解释中说明。这个 MVP 关注的是短列表中的集中度，而不是要求 3-5 条推荐覆盖数据集中所有菜系。

## 使用说明

1. 在左侧调节价值观滑动条：美味、健康、新奇。
2. 设置饮食约束：荤素、辣度、价格、热量、菜系。
3. 在“今日推荐”查看推荐列表和每条解释。
4. 在“透明度”查看目标函数、菜系分布图，以及公平约束前后的差异。
5. 点击“吃这个”记录反馈，下一次推荐会根据本地历史调整新奇度和探索项。
6. 在“反馈统计”查看本地历史和差分隐私噪声统计。

- 你是否觉得价值观滑动条能表达自己的偏好？
- 与随机推荐相比，你是否觉得 EatRight 更透明或更公平？

- 你是否理解差分隐私统计与本地保存历史的意义？
